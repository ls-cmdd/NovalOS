# SMP Bring-up Evidence

## Scope

This document records the current SMP boundary. The normal BIOS and UEFI boot paths do not send AP INIT/SIPI and remain single-core. The experimental path now proves AP entry through Rust and bootstrap GDT/TSS/IDT installation, but no multicore scheduler or concurrent user execution is claimed.

## Verified isolated stages

The vendored low-memory trampoline was assembled with NASM and exercised under QEMU with `-machine q35 -smp 2`. The isolated path reaches protected mode and long mode, writes the handshake byte in the identity-mapped trampoline page, and produces `online=2` in the reproducible `scripts/smp-low-gate.sh` run. The gate continues through the existing syscall and idle markers.

The explicit `smp-experimental` artifact now reaches Rust `ap_entry` on the AP and reports `last_stage=3` after the following sequence: stage 1 from long mode, stage 2 on Rust entry, AP-local GDT/TSS loaded from the low bootstrap stack, a shared immutable IDT built by the BSP in a permanent low frame, and `lidt` performed by the AP. QEMU then continues through hardware IRQ, breakpoint, syscall, user-queue, and idle markers without AP bootstrap faults. The low frame is used because the earlier high-half `Once`-backed AP descriptor objects caused a reproducible reserved-bit page fault before initialization.

## Current blocker

The AP bootstrap context is now proven through stage 3, and a permanent low-memory per-CPU frame records BSP and AP APIC IDs, bootstrap stacks, descriptor readiness, IDT readiness, and online state with atomic fields. The AP installs its record as `IA32_GS_BASE`; `current_per_cpu()` reads the MSR first and only dereferences a nonzero base, so BSP interrupts do not read unmapped address zero. The timer dispatch path has an interrupt-nesting guard backed by the owning per-CPU record. If an AP receives a timer IRQ, it acknowledges the interrupt and increments AP-local `deferred_work`; it does not enter the BSP-owned scheduler or user-context table. This is still not a multicore kernel. APs stop in a controlled halt loop after descriptor/IDT installation; they do not enter the scheduler, run user processes, mutate VFS/IPC/process state, or share the allocator. The user-process registry now uses compare-and-exchange transitions for Ready/Running/Exited/Faulted and mirrors the current process into the owning per-CPU record when available. Process roots and the active address-space record are protected by a `spin::Mutex`; physical-memory offset, kernel-root metadata, and allocator pointer metadata use atomics. The user preemption context table is now a `Mutex<UserContextRegistry>` and the lock is released before `resume_user_context`, preserving saved-context handoff without carrying a lock across a context switch. The allocator object itself remains BSP-owned until allocator locking and page-table mutation protocols are implemented. Process kernel-stack/TSS selection is serialized by a short-lived GDT lock that is released before any context switch. The bounded preemptive context-demo metadata now uses an atomic state lock whose guard is dropped before `switch_context`; QEMU still proves timer preemption and saved-context handoff. This lock does not authorize AP scheduling. Other kernel subsystems still contain BSP-centric `static mut` state and have not passed a complete concurrency audit. Enabling work on APs before that audit would be unsafe and is intentionally excluded.

## Required next work

The next implementation must extend the per-CPU record from bootstrap readiness into ownership of current CPU, interrupt nesting, scheduler queue, and deferred work, then add an explicit AP-local IRQ injection gate that proves the deferred path under hardware delivery. After that, allocator, process roots, VFS, IPC, timer, keyboard, syscall, and scheduler state must be converted from BSP-centric or unsynchronized mutable state to ownership plus locks/atomics. Only then may an AP leave its bootstrap halt loop and execute kernel or user tasks. A `last_stage=3` result proves bootstrap readiness, not SMP scheduling. The low-level proof remains automated by `scripts/smp-low-gate.sh`; the stage-3 experimental proof is currently a separate QEMU run and is not used by release packaging.

## Regression evidence

The stage-3 experimental QEMU run with GS-local per-CPU state and the locked user-context registry passed kernel build, image build, `SMP: discovered=2 attempted=1 online=2 trampoline=true`, `SMP stages: last_stage=3`, `SMP per-CPU ready: 2`, hardware IRQ, breakpoint, syscall, saved-context preemption, process handoff, and idle markers. The only #PF records in QEMU trace are the expected CPL3 guard-page faults from the existing user-fault policy; there is no AP bootstrap #PF, double fault, or triple fault. The low-handshake gate, host ACPI tests, BIOS gate, UEFI gate, and package-release all pass. The package continues to exclude experimental SMP until the shared-state audit is complete.
